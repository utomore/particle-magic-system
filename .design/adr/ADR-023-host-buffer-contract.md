# ADR-023: 宿主緩衝契約——與純值契約並存，取樣器直接寫進宿主記憶體

## 狀態（Status）

accepted（2026-08-20）。修訂 [ADR-0011](../../docs/adr/adr-0011-ffi-c-abi-boundary.md) D3 中「`Data.Vector.Unboxed` 沒有指標介面，逐元素複製是唯一正解」的論斷；補充 [ADR-0006](../../docs/adr/adr-0006-soa-unboxed-buffer.md)（緩衝表徵）與 [ADR-0007](../../docs/adr/adr-0007-effectful-boundary.md)（核心零 IO 的精確含義）。純值觀測契約本身**不變、不棄用**。

## 背景（Context）

現行觀測契約是**純值**：每幀回傳一份全新的粒子緩衝，宿主可長期持有，跨幀重用緩衝被明文裁為「不做」——因為純介面下重寫同一塊記憶體會偷改上一幀。這個裁決在 POC 階段是對的，但 production 審計量出它的代價：

| 項目 | 每幀成本（16384 粒） | 出處 |
|---|---|---|
| 九欄（或六欄）全新配置 | 24–36 B/粒 ≈ 0.4–0.6 MB | 緩衝建構 |
| 平行路徑分片後再串接 | **再一份** 24 B/粒 | 分片結果合併 |
| 力場位移疊加 | 另 24 B/粒 | 三欄位移 ＋ 三欄結果 |
| 取樣器每粒子中介向量 | **~460 B/粒** | func-0022 §9 記帳，未處理 |
| field spell 的每步推進 | 52 B × **整個預算**（非存活數） | 每步重配狀態欄 |
| C ABI copy-out | 逐元素 `poke`，非 `memcpy` | ADR-0011 D3 |

合計在 60 Hz、16384 粒帶場的情境下是每秒數十 MB 的短命垃圾，全部落在**單一 capability 的預設 nursery** 上（[ADR-022](ADR-022-host-runtime-contract.md) 背景第 2 點）。GC 暫停因此直接出現在幀時間裡，而且 POC 時代「GC 壓力需以 eventlog 實測」的風險項從來沒有被量過。

同時，ADR-0011 D3 的技術前提已經不成立：`vector` 套件（核心白名單內）的 Storable 變體可以包裝外部指標，`Data.Vector.Unboxed` 的底層 `ByteArray#` 也有整塊複製到位址的原語。逐元素 poke 不是唯一正解，是當時的選擇。

## 決策（Decision）

### D1（兩條觀測契約並存）

- **純值觀測**（既有）：簽名、語意、逐位元輸出全部不變。它仍是 Haskell 宿主、測試與 golden 的基準，也是「緩衝可長期持有」這個性質的來源。
- **宿主緩衝觀測**（新增）：宿主提供九條（或六條）欄位的記憶體與容量，取樣器**直接寫入**，不經過任何中間緩衝。Haskell 面與 C 面（`pm_observe_into`、`pm_scene_observe_into`）各一個入口。

**等價律 3**：對同一個法術與同一時刻，宿主緩衝觀測寫出的九欄 ≡ 純值觀測回傳的九欄，**逐位元**。這條律與既有的摺疊律、編譯律、平行等價律並列，由同一套 golden 與專屬對照測試守護。

### D2（所有權與生命週期）

宿主擁有記憶體與其生命週期；庫**在呼叫返回後不保留任何指標**。容量規則沿用既有的全有或全無：容量不足回 `PM_ERR_CAPACITY`，一個位元組都不寫。宿主緩衝觀測的輸出在下一次呼叫時被覆寫——這是宿主選這條契約時簽下的條件，文件明列。

### D3（取樣器的寫入目標成為契約參數）

particle-simulation 的主取樣契約增加一個「**寫入目標**」：取樣器對呼叫端提供的可變欄位填寫，而不是自己配置。純值觀測是「寫入目標 = 自己剛配置的欄位，寫完凍結」；宿主緩衝觀測是「寫入目標 = 宿主記憶體」。兩者走**同一條填寫路徑**，等價律 3 因此是結構性的，不靠兩份實作碰巧一致。

分片平行路徑同樣改為對同一組欄位的**不相交切片**直寫，不再「分片各自配置、最後串接」——不相交寫入不引入任何跨執行緒歸約，ADR-0017 的平行等價律原封不動。

### D4（核心零 IO 的精確含義）

ADR-0007 的「核心零 IO」在本 ADR 下精確化為：**核心不執行效果、不依賴任何 IO 專屬的 API、簽名中不出現 `IO` 或效果型別**。對「呼叫端提供的可變欄位」填寫，在核心內以 `ST` 執行，填寫動作對執行單子多型——外殼選擇 `IO` 去對宿主記憶體使用同一個動作。核心的依賴白名單（base、vector、deepseq、parallel）不變，核心仍然不知道指標從哪裡來。

### D5（純值路徑的 copy-out 改為整塊複製）

C ABI 既有的 `pm_observe` 系列保留純值語意（庫內配置、再複製給宿主），但複製改為**每欄一次整塊複製**，取代逐元素 poke。輸出逐位元不變，屬實作升級，列在這裡只為了修正 ADR-0011 D3 的論斷。

## 考慮過的替代方案（Alternatives Considered）

- **直接把純值觀測改成宿主緩衝**：破壞凍結介面與「緩衝可長期持有」的性質，Haskell 宿主與所有測試都要改。並存讓舊宿主零改動。
- **庫內租借池（lease／return API）**：宿主向庫借緩衝、用完歸還。多一組生命週期符號、多一種宿主會犯的錯（忘記歸還），而且引擎通常早就有自己的 pinned／native 記憶體，借庫的反而要再複製一次。D1 讓宿主給記憶體，是最少一層的設計。
- **零複製出借內部指標**：ADR-0011 D3 已否決，理由仍成立——GC 可能搬動未 pin 的記憶體，借出去的指標沒有生命週期保證。
- **只做 D5（memcpy），不做宿主緩衝**：省掉 copy-out 的 N 次 poke，但每幀的配置一個位元組都沒少；GC 壓力的根源還在。
- **允許核心直接用 `IO`**：解決問題最快，但等於放棄 ADR-0007 這條整個專案最重要的紀律。D4 以執行單子多型達到同樣效果而不破界。

## 影響（Consequences）

- particle-simulation：主取樣契約加「寫入目標」參數；路線圖的 `leased-buffer-api` 候選由本 ADR 取代（它的「租借」形式被 D1 的「宿主提供」取代）；`drop-intermediate-v3`、分片直寫、力場步進只走存活槽位，三項成為 P7 的加速骨幹（見 system.md 開發階段）。
- boundary-host：入口模組新增宿主緩衝觀測；純值觀測不動。
- host-runtime：新增 `pm_observe_into`、`pm_scene_observe_into`；既有 `pm_observe` 改整塊複製；C# 綁定新增指標／native array 多載以餵這條路徑；Unity 範例改用它。
- 驗收：穩態（無新施法、無重載）的每幀堆積配置以**配置計數器**斷言為零；等價律 3 進 golden；GC 暫停以 RTS 統計（ADR-022 D6）在 bench 中記錄。
- header 全部是加法，`PM_ABI_VERSION` 不動。
