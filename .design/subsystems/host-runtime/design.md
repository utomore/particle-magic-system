# 嵌入執行期 子系統架構

## 定位與範圍

承接 [system.md](../../system.md)「子系統劃分 → host-runtime」，由 [ADR-025](../../adr/ADR-025-host-runtime-subsystem-split.md) 自 [boundary-host](../boundary-host/design.md) 切出。它回答的問題是：**宿主拿到共享函式庫之後會發生什麼**。boundary-host 定義的是以 Haskell 型別表達的合約；本子系統把那份合約變成宿主進程裡**一個安全、可調、可診斷的共享函式庫**——C 呼叫慣例、RTS 生命週期、例外邊界、執行緒模型、記憶體所有權、封裝與綁定，全部在這裡。

它在 cabal 上本來就是獨立節點：foreign-library 只依賴 `magic-boundary`，加上 `cbits/`、`include/`、`bindings/`、`examples/c/`、`examples/unity/` 五個不屬於任何 Haskell 套件的資料夾。

**做**：C ABI 外殼與標頭、RTS 生命週期與設定、例外防火牆、控制代碼註冊、執行緒模型、宿主緩衝觀測的 C 面與整塊複製、固定時步的 C 面、診斷統計、各語言綁定、非 Haskell 宿主範例、共享函式庫的封裝內容、out-of-process 驗證、`docs/integration.md` 的 C／C++／Unity 章節。

**明確不做**：

- **不含任何魔法語意**。與 boundary-host 同一條鐵律：這裡沒有一行程式碼知道「外圈是展現」。
- **不重新定義邊界層的 Haskell 契約**。C 面只消費 boundary-host 既有條目，**不得比 Haskell 面多知道一件事**；需要新語意時先在 boundary-host 立契約，本子系統再鏡射。
- **不選繪圖 API、不輸出任何渲染器型別**。
- **不接 Haskell 宿主**。Haskell 宿主範例與整合指南的 Haskell 章節留在 boundary-host。
- **不擁有 CI 流程**。發布產物的**內容**（哪些檔、怎麼連結、怎麼命名）由本子系統定義；把它建出來、驗過、上傳，是 [authoring-engineering](../authoring-engineering/design.md) 的事。
- **不替宿主決定 RTS**。capability 數、nursery、GC 模式是宿主的決定；庫不設定就保守，且不自行開 OS 執行緒（[ADR-022](../../adr/ADR-022-host-runtime-contract.md) D1）。

## 對外契約（Public Interface & DTOs）

### C1 C ABI（`include/particle_magic.h`，**只加不改**）

31 個已凍結符號（四組：生命週期、投影、場景、空間摘要）**一個位元都不變**。production 階段新增的符號與結構全部是加法，`PM_ABI_VERSION` 不動。**本文件不複述簽名**——標頭檔是契約權威。新增的結構一律以 `size` 欄開頭，未來加欄不破壞舊宿主。

| 條目 | 契約 |
|---|---|
| **C1.1 生命週期**（既有） | 初始化／施法／推進／觀測／釋放；控制代碼為不透明指標 |
| **C1.2 投影**（既有） | 鏡射 boundary-host C4 |
| **C1.3 場景**（既有） | 鏡射 boundary-host C3 |
| **C1.4 空間摘要**（既有） | 鏡射 boundary-host C5 |
| **C1.5 執行期設定** | 帶設定結構的初始化：capability 數（0 ＝ 依硬體）、nursery 大小、GC 模式；回錯誤碼。無參數的初始化（凍結簽名為 `void`）保留且行為不變。RTS 已初始化時再呼叫帶設定的初始化、或關閉後再初始化，回 `PM_ERR_STATE` |
| **C1.6 宿主緩衝觀測** | 法術與場景各一條：宿主提供九欄（或六欄）記憶體與容量，取樣器**直接寫入**；場景版本含速度欄。全有或全無的容量規則沿用 |
| **C1.7 時步規劃** | 純函數：（步長、單幀最大步數、經過時間、累加器）→（本幀步數、新累加器）。參數與累加器為**雙精度**，與 boundary-host 的時步規劃器**同一份實作、逐位元相同**；既有推進符號的單精度步長簽名不動 |
| **C1.8 診斷** | （控制代碼、統計結構）→ 上一次觀測的存活粒子數、批次數、壁鐘耗時、堆積配置量，以及進程層級的 GC 次數與暫停時間。只讀、不改狀態 |
| **C1.9 錯誤碼** | 既有六個（`PM_OK`、JSON、預算、容量、參數、配額）加 **`PM_ERR_INTERNAL`（−6）**：防火牆攔到的一切（庫的缺陷）；加 **`PM_ERR_STATE`（−7）**：宿主的呼叫順序錯——RTS 未初始化就呼叫、關閉後再初始化、重複帶設定初始化、設定在當前平台無法生效。訊息緩衝沿用 UTF-8 邊界安全截斷 |
| **C1.10 多陣合成** | 不進場景的多陣合成為單一法術控制代碼（鏡射 boundary-host C1.2 的合成入口） |
| **C1.11 場景批次歸屬** | 帶法術識別碼的場景觀測（鏡射 boundary-host C3.4）；既有無歸屬觀測不變，批次資訊**步幅不變** |

**三個既有哨兵註記**（座標系手性、顏色位元組序、決定論的範圍）保留；決定論那一條依 [ADR-024](../../adr/ADR-024-cross-platform-bitexact-trig.md) 改寫為跨平台逐位元。粒子上限在標頭中**永遠釘死**，實際值用查詢——標頭與文件中「查詢今日回傳凍結常數」的過期敘述要修正。

### C2 執行期承諾

| 條目 | 契約 |
|---|---|
| **C2.1 例外防火牆** | 每一個匯出符號攔截一切 Haskell 例外並映射為 `PM_ERR_INTERNAL`（回傳指標者回 NULL、回傳計數者回 −6）。**庫在任何情況下不終止宿主進程**。防火牆是最後一道，攔到即缺陷 |
| **C2.2 執行緒模型** | 不同控制代碼在不同執行緒：可併發，無限制。同一控制代碼：保證**不丟更新**（併發的兩次推進不會只推進一步），**不保證順序**。初始化與關閉原子化；關閉與其他呼叫併發是宿主錯誤。單執行緒宿主零額外成本 |
| **C2.3 控制代碼安全** | 已釋放、重複釋放或偽造的控制代碼回 `PM_ERR_ARGS`，不是未定義行為。表徵為帶世代標籤的不透明控制代碼（修訂 ADR-0011 D4） |
| **C2.4 RTS 歸宿主** | 見 C1.5。庫預設保守（單 capability、預設 GC），不自行開 OS 執行緒。**平台降級條款**：若某平台的 RTS 在宿主呼叫前已由載入器啟動（Windows standalone DLL 的 `DllMain` 為已知嫌疑），capability 數仍以執行期 API 生效，其餘無法生效的欄位回 `PM_ERR_STATE`，且文件逐平台明列哪些欄位生效——**不靜默忽略** |
| **C2.5 關閉語意** | 關閉後本進程不得再使用本庫，兩平台語意一致；Windows standalone DLL 的 `DllMain` refcount 不對稱由實作吸收 |
| **C2.6 `dt` 檢查** | 推進對非有限或負的步長回 `PM_ERR_ARGS` 且狀態不變；合法輸入的輸出逐位元不變 |

### C3 綁定契約

| 條目 | 契約 |
|---|---|
| **C3.1 雙向對帳** | 每份綁定的進入點與常數集合與標頭**雙向相等**，由契約測試守護；標頭加一個符號，綁定沒跟上就紅 |
| **C3.2 C# 兩條路徑** | 託管陣列路徑（既有，blittable、一次 pinning）與**指標／native array 路徑**（新增，供 Burst／Job System 與 GPU 上傳直接餵），兩者呼叫同一組符號 |
| **C3.3 C# 控制代碼包裝** | `SafeHandle` 風格的可釋放包裝：漏釋放有終結器兜底、重複釋放安全；裸指標 API 保留 |
| **C3.4 C++ 包裝** | 標頭級 RAII 包裝：控制代碼的生命週期綁定物件生命週期、錯誤碼轉回傳值（**不**轉例外，宿主可選） |
| **C3.5 腳本後端** | Unity 的 Mono 與 IL2CPP 兩種後端各驗證一次完整生命週期 |

### C4 封裝契約（產物的內容）

| 平台 | 產物 |
|---|---|
| Windows x86_64 | standalone DLL（內嵌 RTS，無外部執行期相依）＋ MinGW 匯入庫 ＋ **MSVC 匯入庫**＋ 標頭 |
| Linux x86_64 | **standalone** `.so`（不再動態相依 libgmp／libffi）＋ 標頭 |
| macOS x86_64／arm64 | `.dylib`（兩架構）＋ 標頭；`install_name` 以 `@rpath` 為基準 |

每份產物附版本檔（套件版本、ABI 世代、建置平台、commit）。產物清單由守門測試與 CI 上傳步驟比對——少一個檔就紅。

### 對外承諾

| 承諾 | 內容 |
|---|---|
| **只加不改** | C 標頭永不移除或改變既有符號、常數、結構版面；新能力一律加新符號 |
| **跨界決定論** | C 路徑與 Haskell 路徑是可測的等價律，對兩條觀測契約皆然 |
| **永不崩潰宿主** | C2.1 |
| **C 面不多知道一件事** | 每個 C 符號都對應 boundary-host 的一條既有契約 |

## 內部模組劃分（Internal Modules）

| 模組 | 位階 | 單一職責 |
|---|---|---|
| **M1 RTS 與初始化** | C 外殼 | RTS 生命週期、設定解析、原子初始化、關閉語意、兩平台差異的吸收 |
| **M2 匯出面** | 外殼 | 匯出符號、參數檢查、錯誤碼分類、訊息緩衝、跨語言資料搬運（整塊複製與宿主緩衝直寫）、時步規劃的 C 面 |
| **M3 防火牆與控制代碼註冊** | 外殼 | 例外攔截與映射、控制代碼的世代標籤與解析、同控制代碼的原子更新 |
| **M4 診斷** | 外殼 | 每控制代碼的觀測統計與進程層級 RTS 統計的收集與匯出 |
| **M5 綁定** | 契約 | C# 綁定（兩條路徑、`SafeHandle`）、C++ RAII 包裝 |
| **M6 非 Haskell 宿主範例** | 契約 | C 最小宿主、C 場景宿主、Unity 元件——每一份都是**按規矩接庫的樣子**，零每幀託管配置 |
| **M7 封裝與整合文件** | 契約 | 連結選項、產物清單與版本檔、`docs/integration.md` 的 C／C++／Unity 章節 |
| **M8 out-of-process 驗證** | 測試 | 真的載入產出的共享函式庫、驅動完整生命週期、驗證防火牆與執行緒模型的測試組 |

**依賴紀律**（機械守護）：M1–M4 只依賴 boundary-host 的入口模組加兩個資料搬運函式庫，**構不到核心**；M5–M7 只依賴標頭；M8 只依賴產出的共享函式庫本身（不連結任何 Haskell 套件）。

## 資料流管線（Data Flow Pipeline）

```text
輸入      宿主呼叫：字串（魔法陣）／控制代碼／宿主緩衝指標與容量／步長
  │
驗證      M2 參數檢查：NULL、負容量、未知平面、非有限 dt → PM_ERR_ARGS
          M3 控制代碼解析：世代標籤不符 → PM_ERR_ARGS
  │
業務處理  M3 防火牆包住下列一切：
            M2 呼叫 boundary-host 對應條目（施法／推進／觀測／查詢／場景／投影／空間摘要）
            Haskell 例外 → PM_ERR_INTERNAL ＋ 訊息
  │
輸出      結果搬運 ─┬─ 純值觀測：每欄一次整塊複製進宿主陣列
                    ├─ 宿主緩衝觀測：取樣器已直接寫入，只填批次資訊
                    └─ 查詢：標量或小結構直接寫出
          M4 順手記下本次觀測的耗時與配置量（只在宿主查詢時才匯出）
          錯誤碼 ＋（有緩衝時）訊息 → 宿主
```

**沒有持久化儲存**；控制代碼的狀態住在 M3 的註冊表，RTS 的狀態住在 M1。

## 模組間公開介面（Module Interfaces）

| # | 呼叫方向 | 契約內容 |
|---|---|---|
| **I1** | M2 → boundary-host | 只呼叫邊界層既有條目，**不得新增語意**；每個 C 符號對應一條 Haskell 契約 |
| **I2** | M2 → M3 | 每個匯出符號的本體都經由防火牆執行；控制代碼一律經註冊表解析，不直接解參考 |
| **I3** | M2 → M1 | 任何匯出符號在 RTS 未初始化或已關閉時回錯誤，不進入 Haskell |
| **I4** | M2 → M4 | 觀測路徑把耗時與配置量交給診斷，成本為兩次時鐘讀取；不查詢的宿主零匯出成本 |
| **I5** | M5／M6／M7 → 標頭 | 綁定、範例、文件只認標頭；由 C3.1 的雙向對帳與範例出貨清單守護 |
| **I6** | M8 → 產物 | 測試以動態載入的方式驅動產出的共享函式庫，與 Haskell 測試套件**不同進程** |

## 使用的技術

| 選型 | 理由 |
|---|---|
| **外部函式庫形式的共享物件，standalone 連結** | 宿主不需要安裝 GHC 執行期；Windows 端需要明確的匯出清單，Linux 端改為 standalone 以消除 libgmp／libffi 的部署相依 |
| **C 呼叫慣例、不透明控制代碼** | 所有語言都能接；表徵可自由演進（世代標籤就是一次演進） |
| **字串進、連續陣列出** | 輸入用字串換取跨語言可攜，輸出用連續陣列換取零轉換；宿主緩衝觀測把「零轉換」推進到「零複製」 |
| **RTS 設定以結構傳入而非命令列字串** | 型別化、可版本化（`size` 欄），宿主不必知道 RTS 旗標語法 |
| **診斷取自 RTS 統計 API** | 不自己量 GC；進程層級數字由執行期提供，庫只轉發 |
| **out-of-process 測試以動態載入驅動** | 唯一能同時驗證匯出清單、RTS 啟動、防火牆與關閉語意的方式；in-process 測試對這四件事全部盲 |

## 開發階段

對應主架構 **P6（不會崩、可交付）、P7（快而穩）、P8（遊戲整合）**三個 production 階段。本子系統是 P6 的主場：P-1、P-4、P-5 三條驗收標準全在這裡出口。內部里程碑：

| 里程碑 | 內容 | 對應 |
|---|---|---|
| **R1 不會崩** | 防火牆、控制代碼世代、RTS 設定與關閉語意、`dt` 檢查 | P6 |
| **R2 可交付** | out-of-process 載入測試、封裝內容、文件修正、時步 C 面 | P6 |
| **R3 零複製** | 宿主緩衝觀測的 C 面、整塊複製、診斷、C# 指標路徑 | P7 |
| **R4 引擎就緒** | 多陣合成與批次歸屬的 C 面、`SafeHandle`、IL2CPP、C++ 包裝 | P8 |

### exception-firewall

- **階段**：階段一
- **負責模組**：M3 防火牆與控制代碼註冊、M2 匯出面
- **實作的 Level 2 介面**：C2.1 例外防火牆、C1.9 錯誤碼（新增 `PM_ERR_INTERNAL`）；建立 I2 的防火牆半邊

- **驗收標準**：每一個匯出符號（含既有 31 個）都經由防火牆；一條刻意觸發內部失敗的測試路徑回 `PM_ERR_INTERNAL` 並在有訊息緩衝時寫入例外文字，進程存活；合法輸入的輸出逐位元不變；標頭新增 `PM_ERR_INTERNAL`（−6）與 `PM_ERR_STATE`（−7）兩個錯誤碼（後者的使用者是 #3、#4），`PM_ABI_VERSION` 不動；C# 綁定的常數對帳同步
