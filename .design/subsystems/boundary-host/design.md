# 邊界與宿主整合 子系統架構

## 定位與範圍

承接 [system.md](../../system.md)「子系統劃分 → boundary-host」。系統對外合約面的 **Haskell 面**，也是「完美的介面化」這條原始目標的落點。它把三個核心子系統包成一份契約，以 Haskell 型別表達；這份契約是 [host-runtime](../host-runtime/design.md)、[render-shell](../render-shell/design.md)、[authoring-engineering](../authoring-engineering/design.md) 三者唯一准許依賴的東西。

C ABI 外殼與各語言綁定自 2026-08-20 起由 host-runtime 擁有（[ADR-025](../../adr/ADR-025-host-runtime-subsystem-split.md)）。兩者的關係只有一句話：**C 面不得比 Haskell 面多知道一件事**——需要新語意時先在本子系統立契約，host-runtime 再鏡射。

**做**：編解碼與版本策略、輸入限制、法術生命週期入口（含施法上下文更新與相位／完成的輪詢查詢）、兩條觀測契約（純值與宿主緩衝）、場景層（含批次歸屬）、維度無關輸出的投影、空間摘要輸出、欄位回灌、Haskell 宿主範例。

**明確不做**：

- **不含任何魔法語意**。這裡沒有一行程式碼知道「外圈是展現」。
- **不選繪圖 API、不輸出任何渲染器型別**。這條在產品級視覺那一輪被正面檢驗過並且維持：自訂著色器、後處理全部進場，但全住 render-shell，輸出契約一個渲染器型別都沒多。
- **不做視錐剔除、不做碰撞判定**。核心沒有相機概念；庫交出保守包絡與佔用格網，判定是宿主的事。
- **不碰 C 呼叫慣例、RTS、執行緒模型與封裝**。那些是 host-runtime 的契約（[ADR-022](../../adr/ADR-022-host-runtime-contract.md)）；本子系統的純函數入口天然可重入，不需要也不提供鎖。

## 對外契約（Public Interface & DTOs）

### C1 Haskell 面

| 條目 | 契約 |
|---|---|
| **C1.1 編解碼** | 位元組 → 魔法陣 或 帶位置的載入錯誤；魔法陣 → 位元組。往返律成立 |
| **C1.2 法術生命週期** | 施法（可能失敗）→ 推進 → 觀測 → 查詢是否結束。**推進與觀測分離**，合成操作等於先推進再觀測 |
| **C1.3 查詢** | 預算計畫、粒子上限、發射器集合與其空間包絡、法術年齡 |
| **C1.4 施法上下文更新** | 推進之間可更新施法者的位置與面向；哪些粒子跟著走由 magic-semantics 的發動點語意決定，本條只負責把新上下文送進去。不更新的法術輸出逐位元不變 |
| **C1.5 相位與完成查詢** | 輪詢式：給法術與時刻，回目前相位，以及自上次查詢以來跨過的界標。沒有回呼——回呼穿不過 C 邊界，也不該穿 |
| **C1.6 輸入限制** | 載入端的全部限制集中一處：位元組上限、節點數上限（委 expr-language）、預算上限（委 magic-semantics）；未知鍵政策明文——執行期**忽略**（向前相容），作者工具的嚴格模式**拒收**（抓錯字） |

### C2 兩條觀測契約

| 條目 | 契約 |
|---|---|
| **C2.1 純值觀測**（凍結） | 觀測回傳一份全新的批次串流；緩衝是宿主可長期持有的純值 |
| **C2.2 宿主緩衝觀測** | 呼叫端提供九欄（或六欄）的可變欄位與容量，取樣器直接寫入；容量不足則一個位元組都不寫；下一次呼叫覆寫。法術與場景各一條，場景版含速度欄 |
| **C2.3 等價律 3** | 對同一法術與時刻，C2.2 寫出的九欄 ≡ C2.1 回傳的九欄，**逐位元**（[ADR-023](../../adr/ADR-023-host-buffer-contract.md)） |

C ABI 的鏡射（含 `include/particle_magic.h` 的哨兵註記與「粒子上限釘死、實際值用查詢」的做法）見 host-runtime 的 C1。

### C3 場景層

| 條目 | 契約 |
|---|---|
| **C3.1 建立與配額** | 場景是純值，帶一個全域粒子上限 |
| **C3.2 入場與拒收** | 施法入場成功回傳法術識別碼與新場景；配額不足則拒收並回報「需求量／剩餘量」，**場景不變** |
| **C3.3 幀循環** | 整場推進、整場觀測、解散單一法術 |
| **C3.4 批次歸屬** | 帶法術識別碼的整場觀測：每個批次附它來自哪個法術。既有的無歸屬觀測不變 |

策略是**先到先得**。按強度加權與優先權搶佔明文否決——它們需要「重要性」這個遊戲層詞彙，庫給的是拒收與剩餘量。

### C4 投影（維度無關輸出的兌現）

| 條目 | 契約 |
|---|---|
| **C4.1 3D** | 恆等——抽象 3D 座標即世界座標 |
| **C4.2 正交** | 給一個視平面與一個 3D 點，回傳**平面座標與深度**。深度供 C4.3 使用 |
| **C4.3 深度排序** | 給視平面與一塊緩衝，回傳一個**穩定**的繪製順序置換 |

### C5 空間摘要（輸出，不是模擬結構）

| 條目 | 契約 |
|---|---|
| **C5.1 有向盒** | 逐發射器的貼合有向包圍盒，以及轉成軸對齊盒的操作 |
| **C5.2 法術級聯集** | 整個法術的包圍盒 |
| **C5.3 佔用格網** | 面座標系對齊的 N³ 格網佔用計數；N 預設 3，27 格恰好壓進一個 32 位元遮罩 |

**這是輸出，不是模擬結構**——它是渲染批次的兄弟，不是力場狀態的兄弟。主架構的「不做空間分割」原地不動。

### C6 欄位回灌

宿主把九欄交回來重建一塊緩衝，供跨語言邊界之後的再處理。

### 對外承諾

| 承諾 | 內容 |
|---|---|
| **唯一依賴點** | 宿主、外殼與 host-runtime 只准經本子系統使用系統，構不到核心內部——由套件結構強制 |
| **零渲染器型別** | 輸出契約不含任何渲染器型別 |
| **C 面不多知道一件事** | host-runtime 的每個 C 符號都對應本子系統的一條既有契約；只加不改的承諾由 host-runtime 對標頭兌現 |
| **兩條觀測逐位元等價** | C2.3 |

## 內部模組劃分（Internal Modules）

| 模組 | 位階 | 單一職責 |
|---|---|---|
| **M1 編解碼** | 邊界 | 序列化雙向轉換、版本欄與遷移策略、輸入限制、載入錯誤的可讀化 |
| **M2 法術入口** | 邊界 | 生命週期、施法上下文更新、相位查詢、兩條觀測的批次組裝（含依混合模式與形狀分批）、力場位移疊加、查詢再匯出 |
| **M3 場景層** | 邊界 | 多法術共存與全域配額、批次歸屬 |
| **M4 投影** | 核心＋邊界 | 投影抽象住核心，對外通道住邊界 |
| **M5 空間摘要** | 核心 | 有向盒與佔用格網。**住核心但語意屬輸出** |
| **M6 欄位回灌** | 邊界 | 九欄重建緩衝 |
| **M7 Haskell 宿主範例與文件** | 契約 | 獨立套件的最小 Haskell 宿主、`docs/integration.md` 的 Haskell 章節 |

**依賴紀律**（機械守護）：邊界層依賴核心加一份白名單；host-runtime 只依賴本子系統加兩個資料搬運函式庫，**構不到核心**。

## 資料流管線（Data Flow Pipeline）

```text
輸入      魔法陣位元組（檔案／字串／跨語言傳入）
  │
驗證      M1 解碼：結構、值域、算式文法
          失敗 → 帶位置的載入錯誤 →（C 面）錯誤碼 ＋ 訊息緩衝
  │
業務處理  M2 施法 → 呼叫 magic-semantics 編譯（可能回預算超額）
          M2 更新上下文（選配）→ 下一次推進起生效
          M2 推進 → 呼叫 particle-simulation 的時步規劃與力場積分
          M2 觀測 → 取樣（寫入目標 = 自配欄位 或 呼叫端欄位）＋ 疊加位移 ＋ 分批
          M3（若走場景）→ 配額檢查、整場推進與觀測（可帶歸屬）
  │
輸出      渲染批次串流 ─┬─→ 純值：Haskell 宿主直接持有；host-runtime 整塊複製給 C 宿主
                        ├─→ 宿主緩衝：已寫進呼叫端欄位，只回批次資訊
                        ├─→ 相位／完成（輪詢查詢）
                        └─→ M4 投影／M5 空間摘要（旁支查詢，不在每幀主路徑上）
```

**沒有持久化儲存**。場景是純值，法術控制代碼的狀態住在呼叫端。

## 模組間公開介面（Module Interfaces）

| # | 呼叫方向 | 契約內容 |
|---|---|---|
| **I1** | M2 → magic-semantics | 編譯與靜態查詢 |
| **I2** | M2 → particle-simulation | 取樣、力場積分、時步規劃 |
| **I3** | M2 內部 | 位移依存活槽位列舉對齊緩衝的列後相加 |
| **I4** | M3 → M2 | 場景層建立在法術入口之上，**不繞過它** |
| **I5** | host-runtime → M1／M2／M3／M4／M5／M6 | 入站約束：C 面只呼叫本子系統既有條目，**不得新增語意**（host-runtime 的 I1 是同一條的另一端） |
| **I6** | M5 → magic-semantics | 空間摘要用核心的區間算術收緊界，而非複製一份 |

## 使用的技術

| 選型 | 理由 |
|---|---|
| **序列化用 JSON** | 跨語言的建構語言：宿主不需要懂 Haskell 資料型別，丟字串進來就好 |
| **連續陣列出** | 輸出用連續的無包裝欄位換取零轉換；宿主緩衝觀測讓呼叫端決定那些欄位住哪裡 |
| **執行單子多型的填寫** | 取樣器對「呼叫端提供的欄位」填寫，核心內以 `ST`、外殼以 `IO` 執行同一個動作——這是宿主緩衝觀測不破壞「核心零 IO」的理由（ADR-023 D4） |
| **公開 sublibrary** | 外部專案可直接依賴，不必抄程式碼 |

## 開發階段

對應主架構 P1～P2（已達成：唯一入口成立 → 多法術 → 空間輸出），production 階段承擔 **P7** 的宿主緩衝觀測（Haskell 面契約先行）與 **P8** 遊戲整合的 Haskell 面（上下文更新、相位查詢、批次歸屬、輸入強化、schema v2）。C ABI 的歷史（11 → 31 個符號而 ABI 世代未動）自 2026-08-20 起記在 host-runtime。

### framework-skeleton

- **階段**：階段一（已交付）

- **當初的驗收標準**：一份魔法陣能被載入、施法、逐幀推進與觀測，並產出批次；外殼與宿主**實體上構不到核心內部**（由套件結構強制並有測試守護）；推進與觀測可分離呼叫且合成等於先推後觀
- **明確不做**：不含魔法語意；不做場景層；不上 C ABI

### ortho2d-projection

- **階段**：階段一（已交付）
- **負責模組**：M4 投影

- **明確不做**：不決定螢幕映射與縮放（那是外殼的呈現選擇）；不做透視投影以外的相機模型

### haskell-host-onboarding

- **階段**：階段二（已交付）

- **明確不做**：不做可交付的像素風參考實作（食譜有，範例沒走過）；不把外殼的螢幕映射提升成對外介面

### scene-layer

- **階段**：階段三（已交付）
- **負責模組**：M3 場景層、M2 法術入口

- **明確不做**：不做按強度加權或優先權搶佔（需要遊戲層詞彙）；不做批次歸屬（屬階段六 #4）；C 面屬 host-runtime

### spatial-output-anchors

- **階段**：階段四（已交付）
- **負責模組**：M5 空間摘要（C 面鏡射記在 host-runtime）

## Feature 契約卡

### host-buffer-observe

- **階段**：階段五
- **負責模組**：M2 法術入口、M3 場景層
- **實作的 Level 2 介面**：C2.2 宿主緩衝觀測、C2.3 等價律 3；「兩條觀測逐位元等價」承諾
- **資料流管線段落**：業務處理段的觀測（寫入目標 = 呼叫端欄位）到輸出段的宿主緩衝分支
- **驗收標準**：呼叫端提供的九欄（或六欄）被直接填寫，與純值觀測的輸出逐位元相同，對出貨的每一份範例陣與每一幀皆斷言；容量不足時一個位元組都不寫並回報；場景版本含速度欄；力場位移的疊加與分批在兩條契約下結果一致；純值觀測的簽名與輸出不變
- **明確不做**：不改變純值觀測；不在本子系統配置任何中間欄位（否則等價律 3 成立但零配置不成立）；不做 C 面（屬 host-runtime）；不在 particle-simulation 的寫入目標契約落地前先做

### caster-context-update

- **階段**：階段六
- **負責模組**：M2 法術入口
- **實作的 Level 2 介面**：C1.4 施法上下文更新
- **資料流管線段落**：業務處理段——更新在下一次推進起生效
- **驗收標準**：宿主能在推進之間更新施法者位置與面向；哪些發射器跟著走完全由 magic-semantics 的發動點語意決定，本子系統不自己判斷；從不更新的法術輸出逐位元不變；場景層的法術同樣可更新
- **明確不做**：不定義跟隨語意；不做插值或平滑（宿主給什麼就是什麼）；不做 C 面

### phase-poll-queries

- **階段**：階段六
- **負責模組**：M2 法術入口
- **實作的 Level 2 介面**：C1.5 相位與完成查詢
- **資料流管線段落**：輸出段的旁支查詢
- **驗收標準**：宿主能查目前相位，以及自上次查詢以來跨過的界標（以時刻對比實作，不需要庫記住宿主）；查詢不改變任何狀態；結果與 magic-semantics 的階段查詢一致
- **明確不做**：不做回呼；不讓庫保存每個宿主的查詢游標（宿主自己帶上次的時刻）

### scene-batch-attribution

- **階段**：階段六
- **負責模組**：M3 場景層
- **實作的 Level 2 介面**：C3.4 批次歸屬
- **資料流管線段落**：輸出段的場景分支
- **驗收標準**：宿主能知道每個批次屬於哪個法術；既有的無歸屬觀測完全不變；批次的切分與順序不變
- **明確不做**：不改變批次的切分方式；不做 C 面（屬 host-runtime 的 scene-attribution-c）

### input-hardening

- **階段**：階段六
- **負責模組**：M1 編解碼
- **實作的 Level 2 介面**：C1.6 輸入限制
- **資料流管線段落**：驗證段
- **驗收標準**：位元組上限、節點數上限、預算上限各有測試且錯誤訊息指出是哪一條；未知鍵在執行期被忽略、在嚴格模式被拒收並指出鍵名與位置；出貨的全部範例陣在嚴格模式下通過；既有合法檔案的輸出逐位元不變
- **明確不做**：不改變任何合法輸入的語意；不做結構深度以外的 JSON 解析防護（那是序列化函式庫的責任）；嚴格模式的 CLI 旗標屬 authoring-engineering

### schema-v2-migrate

- **階段**：階段六
- **負責模組**：M1 編解碼
- **實作的 Level 2 介面**：擴充 C1.1，新增舊版解碼器與版本遷移
- **資料流管線段落**：驗證段
- **驗收標準**：版本欄遞增後，舊版檔案仍能載入並被遷移為新版資料；核心永遠只處理最新版；兩個版本各有 golden 守護
- **明確不做**：不在沒有實際版本變更時預先建構遷移機制；不支援向下遷移

### time-varying-anchors

- **階段**：階段六
- **負責模組**：M5 空間摘要、M2 法術入口
- **實作的 Level 2 介面**：擴充 C5.1／C5.2 的時間參數化語意（「此刻」而非「至此刻為止」），並在施法者移動後仍給出保守界
- **資料流管線段落**：輸出段的旁支查詢
- **驗收標準**：空間查詢能問「此刻」的界而不只是累積界；施法者移動後的包絡仍保守；既有查詢的結果與語意不變
- **明確不做**：不讓空間摘要參與模擬；不改變既有包絡的逐位元結果
