# 邊界與宿主整合 子系統架構

## 定位與範圍

承接 [system.md](../../system.md)「子系統劃分 → boundary-host」。六塊裡唯一**面向外界**的一塊，也是「完美的介面化」這條原始目標的落點。它把三個核心子系統包成一份契約，並用**三種呼叫慣例**送出去。

涵蓋整個邊界層，加上外殼位階的 C ABI 外殼——把後者收進來的理由是：它與邊界層共用**同一份合約**，只是換一種呼叫慣例。**C 面不得比 Haskell 面多知道一件事。**

**做**：編解碼與版本策略、法術生命週期入口、場景層、維度無關輸出的投影、空間摘要輸出、C ABI 與各語言參考綁定。

**明確不做**：

- **不含任何魔法語意**。這裡沒有一行程式碼知道「外圈是展現」。
- **不選繪圖 API、不輸出任何渲染器型別**。這條在產品級視覺那一輪被正面檢驗過並且維持：自訂著色器、後處理全部進場，但全住 [render-shell](../render-shell/design.md)，輸出契約一個渲染器型別都沒多。
- **不做視錐剔除、不做碰撞判定**。核心沒有相機概念；庫交出保守包絡與佔用格網，判定是宿主的事。
- **不管執行緒安全**。目前無內部鎖，多執行緒宿主需自行序列化控制代碼存取。

## 對外契約（Public Interface & DTOs）

### C1 Haskell 面

| 條目 | 契約 |
|---|---|
| **C1.1 編解碼** | 位元組 → 魔法陣 或 帶位置的載入錯誤；魔法陣 → 位元組。往返律成立 |
| **C1.2 法術生命週期** | 施法（可能失敗）→ 推進 → 觀測 → 查詢是否結束。**推進與觀測分離**，合成操作等於先推進再觀測 |
| **C1.3 查詢** | 預算計畫、粒子上限、發射器集合與其空間包絡、法術年齡 |

### C2 C ABI（`include/particle_magic.h`，**只加不改**）

31 個匯出符號，四組：生命週期、投影、場景、空間摘要。**本文件不複述簽名**——標頭檔本身就是契約權威，複述只會製造第二份會過期的真相。

| 條目 | 契約 |
|---|---|
| **C2.1 生命週期** | 初始化／施法／推進／觀測／釋放，控制代碼為不透明指標 |
| **C2.2 投影** | 鏡射 C4 的兩條查詢 |
| **C2.3 場景** | 鏡射 C3 全部 |
| **C2.4 空間摘要** | 鏡射 C5 全部 |

三個寫進標頭的**哨兵註記**（不寫不會壞，寫了才不咬人）：座標系手性、顏色位元組序、決定論的範圍。粒子上限在標頭中**永遠釘死**，實際值改用查詢取得——這是「值可以動、合約不動」的做法。

### C3 場景層

| 條目 | 契約 |
|---|---|
| **C3.1 建立與配額** | 場景是純值，帶一個全域粒子上限 |
| **C3.2 入場與拒收** | 施法入場成功回傳法術識別碼與新場景；配額不足則拒收並回報「需求量／剩餘量」，**場景不變** |
| **C3.3 幀循環** | 整場推進、整場觀測、解散單一法術 |

策略是**先到先得**。按強度加權與優先權搶佔明文否決——它們需要「重要性」這個遊戲層詞彙，庫給的是拒收與剩餘量。

### C4 投影（維度無關輸出的兌現）

| 條目 | 契約 |
|---|---|
| **C4.1 3D** | 恆等——抽象 3D 座標即世界座標 |
| **C4.2 正交** | 給一個視平面與一個 3D 點，回傳**平面座標與深度**。深度供 C4.3 使用 |
| **C4.3 深度排序** | 給視平面與一塊緩衝，回傳一個**穩定**的繪製順序置換 |

### C5 空間摘要（輸出，不是模擬結構）

| 條目 | 契約 |
|---|---|
| **C5.1 有向盒** | 逐發射器的貼合有向包圍盒，以及轉成軸對齊盒的操作 |
| **C5.2 法術級聯集** | 整個法術的包圍盒 |
| **C5.3 佔用格網** | 面座標系對齊的 N³ 格網佔用計數；N 預設 3，27 格恰好壓進一個 32 位元遮罩 |

**這是輸出，不是模擬結構**——它是渲染批次的兄弟，不是力場狀態的兄弟。主架構的「不做空間分割」原地不動。

### C6 欄位回灌

宿主把九欄交回來重建一塊緩衝，供跨語言邊界之後的再處理。

### 對外承諾

| 承諾 | 內容 |
|---|---|
| **唯一依賴點** | 宿主與外殼只准經本子系統使用系統，構不到核心內部——由套件結構強制 |
| **零渲染器型別** | 輸出契約不含任何渲染器型別 |
| **只加不改** | C 標頭永不移除或改變既有符號；新能力一律加新符號 |
| **跨界決定論** | C 路徑與 Haskell 路徑是可測的等價律 |

## 內部模組劃分（Internal Modules）

| 模組 | 位階 | 單一職責 |
|---|---|---|
| **M1 編解碼** | 邊界 | 序列化雙向轉換、版本欄與遷移策略、載入錯誤的可讀化 |
| **M2 法術入口** | 邊界 | 生命週期、輸出批次組裝（含依混合模式與形狀分批）、力場位移疊加、查詢再匯出 |
| **M3 場景層** | 邊界 | 多法術共存與全域配額 |
| **M4 投影** | 核心＋邊界 | 投影抽象住核心，對外通道住邊界 |
| **M5 空間摘要** | 核心 | 有向盒與佔用格網。**住核心但語意屬輸出** |
| **M6 欄位回灌** | 邊界 | 九欄重建緩衝 |
| **M7 C ABI 外殼** | 外殼 | 匯出符號、控制代碼生命週期、錯誤碼分類、跨語言資料搬運 |
| **M8 參考綁定與範例** | 契約 | 一份 C# 綁定與三份最小宿主範例（C／Haskell／Unity） |

**依賴紀律**（機械守護）：邊界層依賴核心加一份白名單；C ABI 外殼只依賴邊界層加兩個資料搬運函式庫，**構不到核心**。

## 資料流管線（Data Flow Pipeline）

```text
輸入      魔法陣位元組（檔案／字串／跨語言傳入）
  │
驗證      M1 解碼：結構、值域、算式文法
          失敗 → 帶位置的載入錯誤 →（C 面）錯誤碼 ＋ 訊息緩衝
  │
業務處理  M2 施法 → 呼叫 magic-semantics 編譯（可能回預算超額）
          M2 推進 → 呼叫 particle-simulation 的時步規劃與力場積分
          M2 觀測 → 取樣 ＋ 疊加位移 ＋ 依混合模式與形狀分批
          M3（若走場景）→ 配額檢查、整場推進與觀測
  │
輸出      渲染批次串流 ─┬─→ Haskell 宿主（純值）
                        ├─→ C 宿主（九欄 copy-out ＋ 批次資訊）
                        └─→ M4 投影／M5 空間摘要（旁支查詢，不在每幀主路徑上）
```

**沒有持久化儲存**。場景是純值，法術控制代碼的狀態住在呼叫端。

## 模組間公開介面（Module Interfaces）

| # | 呼叫方向 | 契約內容 |
|---|---|---|
| **I1** | M2 → magic-semantics | 編譯與靜態查詢 |
| **I2** | M2 → particle-simulation | 取樣、力場積分、時步規劃 |
| **I3** | M2 內部 | 位移依存活槽位列舉對齊緩衝的列後相加 |
| **I4** | M3 → M2 | 場景層建立在法術入口之上，**不繞過它** |
| **I5** | M7 → M1／M2／M3／M4／M6 | C 面只呼叫邊界層既有條目，**不得新增語意** |
| **I6** | M5 → magic-semantics | 空間摘要用核心的區間算術收緊界，而非複製一份 |

## 使用的技術

| 選型 | 理由 |
|---|---|
| **序列化用 JSON** | 跨語言的建構語言：C 宿主不需要懂 Haskell 資料型別，丟字串進來就好 |
| **外部函式庫形式的共享物件** | 不引入額外的繫結產生器；Windows 端需要明確的匯出清單，否則連得起來但宿主解不到符號 |
| **字串進、連續陣列出** | 輸入用字串換取跨語言可攜，輸出用連續陣列換取零轉換——宿主拿到的就是可直接餵頂點緩衝的東西 |
| **不透明控制代碼** | 內部表徵可自由演進 |
| **公開 sublibrary** | 外部專案可直接依賴，不必抄程式碼 |

## 開發階段

對應主架構 P1～P2，並承擔「可用的庫」這個維度。內部里程碑四個，皆已達成：唯一入口成立 → 第二種消費模式 → 多法術 → 空間輸出。凍結的 C 符號自 11 個成長到 31 個，而 ABI 世代**未動**——這是「只加不改」實際運作的證據。

### framework-skeleton

- **階段**：階段一（已交付）
- **負責模組**：M1 編解碼、M2 法術入口
- **實作的 Level 2 介面**：C1.1 編解碼、C1.2 法術生命週期；建立 I1、I2、I3 與「唯一依賴點」「零渲染器型別」兩條承諾
- **資料流管線段落**：全段——從位元組進來到渲染批次出去
- **當初的驗收標準**：一份魔法陣能被載入、施法、逐幀推進與觀測，並產出批次；外殼與宿主**實體上構不到核心內部**（由套件結構強制並有測試守護）；推進與觀測可分離呼叫且合成等於先推後觀
- **明確不做**：不含魔法語意；不做場景層；不上 C ABI

### ortho2d-projection

- **階段**：階段一（已交付）
- **負責模組**：M4 投影
- **實作的 Level 2 介面**：C4.1 3D、C4.2 正交、C4.3 深度排序
- **資料流管線段落**：輸出段的旁支查詢
- **當初的驗收標準**：同一份輸出換投影即換維度、核心零變更；正交投影同時回傳平面座標與深度；排序是穩定置換（同深度的粒子維持原相對順序）
- **明確不做**：不決定螢幕映射與縮放（那是外殼的呈現選擇）；不做透視投影以外的相機模型

### ffi-foreign-library

- **階段**：階段二（已交付）
- **負責模組**：M7 C ABI 外殼
- **實作的 Level 2 介面**：C2.1 生命週期；建立 I5 與「只加不改」「跨界決定論」兩條承諾
- **資料流管線段落**：全段的 C 面鏡射——字串進、九欄出
- **當初的驗收標準**：非 Haskell 宿主能驅動完整生命週期；**C 路徑與 Haskell 路徑的輸出逐位元相同**（可測等價律）；控制代碼為不透明指標且釋放後不可用；錯誤以錯誤碼加訊息緩衝回報
- **明確不做**：C 面不得比 Haskell 面多知道任何語意；不繪圖；不做執行緒安全

### host-integration-surface

- **明確不做**：不新增模擬語意；不為每個引擎各寫一套綁定

### haskell-host-onboarding

- **階段**：階段二（已交付）
- **負責模組**：M8 參考綁定與範例

### scene-layer

- **階段**：階段三（已交付）
- **負責模組**：M3 場景層、M2 法術入口

- **明確不做**：不做按強度加權或優先權搶佔（需要遊戲層詞彙）；不做批次歸屬（屬 #9）；不上 C ABI（屬 #7）

- **當初的驗收標準**：有向盒顯著貼合於既有的保守立方體；法術級聯集可用；N³ 格網的佔用可查且 N=3 時能壓進一個 32 位元遮罩；主效果可有多個發動點且能量等分；既有法術輸出逐位元不變
- **明確不做**：不做碰撞判定本身（庫給資訊，判定在宿主）；不把空間摘要變成模擬結構；不做時變發動點（屬 #11）

## Feature 契約卡

### scene-batch-attribution

- **階段**：階段五（候選）
- **負責模組**：M3 場景層、M7 C ABI 外殼
- **實作的 Level 2 介面**：擴充 C3.3 幀循環，新增一條帶歸屬資訊的觀測；C 面對應加平行輸出陣列
- **資料流管線段落**：輸出段的場景分支
- **驗收標準**：宿主能知道每個批次屬於哪個法術；既有的無歸屬觀測完全不變；C 面的批次資訊步幅**不變**
- **明確不做**：不改變批次的切分方式；不讓 C 面比 Haskell 面先有這個能力

### cast-many-c-abi

- **階段**：階段五（候選）
- **負責模組**：M7 C ABI 外殼
- **實作的 Level 2 介面**：C2.1 生命週期新增一條「多陣合成為單一法術」的入口
- **資料流管線段落**：業務處理段的合成分支的 C 面鏡射
- **驗收標準**：C 宿主能把多張陣合成為一個法術控制代碼而不必建立場景；ABI 世代不變
- **明確不做**：不改變合成的語意（那在 magic-semantics）；不取代場景層

### time-varying-anchors

- **階段**：階段五（候選）
- **負責模組**：M5 空間摘要、M2 法術入口
- **實作的 Level 2 介面**：擴充 C5.1／C5.2 的時間參數化語意（「此刻」而非「至此刻為止」）；發動點可隨施法者移動
- **資料流管線段落**：輸出段的旁支查詢
- **驗收標準**：發動點能跟隨施法者；空間查詢能問「此刻」的界而不只是累積界；既有查詢的結果與語意不變
- **明確不做**：不讓空間摘要參與模擬；不改變既有包絡的逐位元結果

### schema-v2-migrate

- **階段**：階段五（候選）
- **負責模組**：M1 編解碼
- **實作的 Level 2 介面**：擴充 C1.1，新增舊版解碼器與版本遷移
- **資料流管線段落**：驗證段
- **驗收標準**：版本欄遞增後，舊版檔案仍能載入並被遷移為新版資料；核心永遠只處理最新版；兩個版本各有 golden 守護
- **明確不做**：不在沒有實際版本變更時預先建構遷移機制；不支援向下遷移

### more-language-bindings

- **階段**：階段五（候選）
- **負責模組**：M8 參考綁定與範例
- **實作的 Level 2 介面**：無新增，消費 C2 全部
- **資料流管線段落**：全段的另一語言鏡射
- **驗收標準**：新語言的綁定能驅動完整生命週期，且其符號清單由契約測試與標頭比對
- **明確不做**：不為此改動 C 契約；不承諾維護所有語言——等真實宿主需求

### ffi-thread-safety

- **階段**：階段五（候選）
- **負責模組**：M7 C ABI 外殼
- **實作的 Level 2 介面**：為 C2 全部補上明文的執行緒模型（或內部鎖）
- **資料流管線段落**：全段的併發語意
- **驗收標準**：明文寫出哪些操作可併發、哪些必須序列化，並有對應測試；單執行緒宿主的效能不因此下降
- **明確不做**：不做無鎖化改寫；不改變任何既有符號的簽名
