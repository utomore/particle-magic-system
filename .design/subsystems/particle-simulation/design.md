# 粒子模擬 子系統架構

## 定位與範圍

承接 [system.md](../../system.md)「子系統劃分 → particle-simulation」。住**純核心**（唯一例外是固定時步規劃器，見下），回答的問題是「**這一幀長什麼樣**」——拿 [magic-semantics](../magic-semantics/design.md) 編出來的法術，加上一個時間，算出一整塊粒子緩衝。

它是混合粒子模型的實作：**解析為主，力場為輔**。多數魔法的粒子位置是時間的純函數（無狀態、可任意快轉倒帶）；需要粒子被外力拉扯時才啟用力場層，那是整個系統唯一的跨幀狀態。

**做**：SoA 粒子緩衝的表徵與不變量、解析層取樣、力場層的固定時步純狀態轉移與位移疊加、效能治理（時間窗剔除、每發射器提升、平行分片、預算）、固定時步規劃。

**明確不做**：

- **不編譯魔法陣**。編譯後的法術是輸入，怎麼來的不關本子系統的事。
- **不繪製、不投影**。輸出是抽象 3D 座標的緩衝。
- **不做粒子對粒子的互動**。力場層只支援「場對粒子」。碰撞、鄰居查詢、空間分割是主架構明列的**永久非目標**。
- **不自行跨幀重用緩衝**。純值契約下觀測回傳的緩衝是宿主可長期持有的純值，跨幀重寫同一塊會偷改上一幀。宿主緩衝契約（[ADR-023](../../adr/ADR-023-host-buffer-contract.md)）把重用的決定交給呼叫端：取樣器對呼叫端給的欄位填寫，**不保留、不配置、不決定它的生命週期**。
- **不用 libm 的超越函數**（自 [ADR-024](../../adr/ADR-024-cross-platform-bitexact-trig.md) 起）。`sin`／`cos` 等不受正確捨入保證的函數改走本庫的確定性實作；`sqrt` 有保證，維持原生。

## 對外契約（Public Interface & DTOs）

### C1 取樣

| 條目 | 契約 |
|---|---|
| **C1.1 主取樣** | （編譯後的法術、施法上下文、時間）→ 一塊粒子緩衝。純函數 |
| **C1.2 序列／平行等價** | 粒子數超過門檻時走分片平行路徑，否則走序列路徑。兩者結果**逐位元相同，且與執行緒數無關**——決定論由切分方式結構性保證，不靠碰巧 |
| **C1.3 寫入目標** | 主取樣對「呼叫端提供的可變欄位」填寫：（法術、上下文、時間、目標欄位）→ 填好的列數。C1.1 是「目標 = 自己剛配置的欄位，寫完凍結」的特例；兩者走**同一條填寫路徑**。填寫動作對執行單子多型——核心內以 `ST`，外殼可在宿主記憶體上以 `IO` 執行同一個動作（ADR-023 D4） |
| **C1.4 等價律 3** | 對同一輸入，C1.3 填出的九欄 ≡ C1.1 回傳的九欄，逐位元；平行路徑的分片對同一組欄位的不相交切片直寫，不再串接 |
| **C1.5 跨平台逐位元** | 同一輸入在所有 Tier 1 平台產出相同的九欄位元（ADR-024）。前提：單精度確定的 SIMD 單元、呼叫端不改動浮點控制字 |

### C2 粒子緩衝（DTO）

九個平行的無包裝數值欄加一個計數：三軸位置、尺寸、生命、封裝顏色，以及三軸**選配**速度。

| 不變量 | 內容 |
|---|---|
| **欄位長度** | 前六欄長度皆等於計數；三個速度欄要嘛全空、要嘛全滿，且三欄同步——**絕不半滿** |
| **前六欄凍結** | 名稱、型別、順序、語意自骨架時期起逐位元未變。第三方宿主與 C ABI 都依賴這件事 |

消費者只需問一個問題（「這塊緩衝有速度嗎」）就能決定怎麼讀，不必各自防禦。

### C3 力場層

| 條目 | 契約 |
|---|---|
| **C3.1 場加速度** | （場的集合、一個位置）→ 加速度。**只吃位置**，不吃速度 |
| **C3.2 每步輸入** | （法術、上下文、時間）→ 本步各槽位的年齡與解析基準位置 |
| **C3.3 固定步積分** | （場、步長、每步輸入、上一步狀態）→ 新狀態。只作用於**施放階段**的槽位 |
| **C3.4 位移取出** | 依存活槽位的列舉順序取出累積位移 |

### C4 對齊面（解析層外露的兩個半邊）

| 條目 | 契約 |
|---|---|
| **C4.1 單粒子位置** | 算出某個發射器的某顆粒子在某個年齡的位置。力場層以此取得解析基準，兩層因此共用**同一份**位置定義而非兩份拷貝 |
| **C4.2 存活槽位列舉** | 某時刻所有存活槽位的有序列舉，**其順序恰為緩衝的列順序**。這是位移能對齊回緩衝的唯一依據 |

### C5 固定時步規劃

（步長、單幀最大步數、經過時間、累加器）→（本幀要跑幾步、新的累加器）。積壓超過上限時**截斷並丟棄餘額**：模擬變慢，而不是凍結。

### 組合點語意（本子系統對外最重要的一條約定）

```text
最終位置 = 解析位置 + 力場位移
```

力場層**不吃粒子緩衝**——緩衝的列每幀變動，不能當身分。它以編譯期固定的槽位身分為鍵，疊加時用 C4.2 的列舉對齊。

### 兩條額外的不變量

| 不變量 | 內容 |
|---|---|
| **零場免費** | 沒有力場的法術**結構性跳過**整層，成本與力場層不存在時完全相同——不是「算出零位移」，是整層不進入 |
| **平行等同** | 見 C1.2 |

## 內部模組劃分（Internal Modules）

| 模組 | 層 | 單一職責 |
|---|---|---|
| **M1 SoA 緩衝** | 核心 | 緩衝的表徵、不變量檢查、單趟填充的建構路徑（含速度欄的選配路徑） |
| **M2 解析層** | 核心 | 主取樣與分片平行、單粒子位置與存活槽位列舉、時間窗剔除、形狀取樣、速度的有限差分 |
| **M3 力場層** | 核心 | 場的求值、每槽位積分狀態、固定步積分與位移取出 |
| **M4 時步規劃** | **邊界** | 累加器與截斷護欄。**唯一不住核心的模組**：它是純函數，放邊界層是為了讓外殼主迴圈與 C ABI 消費**同一份**規劃器而非兩份拷貝 |

依賴方向：`M1 ← M2 ← M3`（力場層以解析層的位置為基準），`M4` 不依賴任何人。

## 資料流管線（Data Flow Pipeline）

```text
輸入      編譯後的法術 ＋ 施法上下文 ＋ 這一幀經過的時間
  │
驗證      無。輸入來自編譯器，型別已保證合法；
          唯一的執行期防護是 M4 的步數截斷
  │
業務處理  ┌─ M4 規劃：經過時間 → 本幀要跑幾步（固定步長）
          │
          ├─ 每一步（僅當法術帶場）：
          │    M2 算出本步各槽位的解析基準位置（C3.2）
          │    M3 以半隱式積分推進每槽位狀態（C3.3）
          │
          └─ 每一幀恰一次：
               M2 取樣（C1.1）：時間窗剔除 → 每發射器提升 →
               形狀取樣／軌跡／算式 → 分片平行 → 單趟填滿緩衝
  │
儲存      力場狀態是**系統唯一的跨幀狀態**；零場的法術完全沒有這一項
  │
輸出      粒子緩衝 ＋（若有場）依 C4.2 順序取出的位移
          兩者在 boundary-host 相加，成為最終位置
```

## 模組間公開介面（Module Interfaces）

| # | 呼叫方向 | 契約內容 |
|---|---|---|
| **I1** | M2 → M1 | 取樣以「先數後填」的方式建構緩衝：先算出確切列數，再單趟填滿，**零中介結構** |
| **I2** | M3 → M2 | 力場層向解析層要每槽位的年齡與基準位置（C3.2 的實作依據）；這是「兩層共用同一份位置定義」的接點 |
| **I3** | M2 內部 | 分片的切分只依法術與時間決定，**與執行緒數無關**——這是 C1.2 決定論的結構性保證所在 |
| **I4** | M3 → M1 | 力場狀態以攤平的無包裝欄表示。**這個表徵明文不凍結**，是它能被重寫的理由 |

## 使用的技術

沿用核心的依賴白名單。子系統特有的三項選型：

| 選型 | 理由 |
|---|---|
| **SoA ＋ 無包裝向量** | 無指標追蹤、快取友善；垃圾回收只見少數大塊而非十萬個小物件；連續記憶體可直接餵給渲染後端與 C ABI |
| **先數後填的單趟建構** | 先算出確切大小再一次填滿，零中介。取代了「先建串列再轉向量」的舊寫法 |
| **純策略式平行** | 平行取樣的唯一可接受手段：它只選擇求值順序、永不改變值，因此不破壞「核心零 IO、簽名中無效果型別」。以執行緒或不安全介面實作做不到這一點 |

## 開發階段

對應主架構 P1（骨架）與 P2（可用的庫）的效能半場，並承擔全部量化目標。內部里程碑三個，皆已達成：

| 里程碑 | 內容 |
|---|---|
| **M1 兩層模型成立** | 解析層與力場層各自可用，且組合語意釘死 |
| **M2 達到吞吐目標** | 1 萬～10 萬粒 |
| **M3 多核與新欄** | 平行取樣、速度欄的選配加欄範式 |

**進度數字會低估這個子系統的成熟度**：M1 的緩衝與取樣器、M3 的兩項，主場都記在別的子系統（見 [legacy-map.md](../../legacy-map.md)）。緩衝與解析層幾乎每一輪都被動到，這是全專案最常見的「參與者」。

- **明確不做**：不做跨幀緩衝重用（純介面下違反引用透明，屬 #7）；不改變任何對外契約；不動粒子上限值

## Feature 契約卡

### drop-intermediate-v3

- **階段**：階段三（候選）
- **負責模組**：M2 解析層
- **實作的 Level 2 介面**：無新增，優化 C1.1 的內部路徑
