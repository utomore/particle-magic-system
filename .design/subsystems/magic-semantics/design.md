# 魔法語意 子系統架構

## 定位與範圍

承接 [system.md](../../system.md)「子系統劃分 → magic-semantics」。這一塊住**純核心**，回答的問題是「**魔法是什麼**」——一張魔法陣作為資料，它的結構長怎樣、每個槽位的符文代表什麼語意、這些語意如何被一個預先寫好的解釋器折成一組發射器。它是「Circle as Data」與「特效即魔法」兩條理念的實際落點。

**做**：

- 魔法陣的結構與其硬合約（外圈 2 層／夾層 1 層／內圈 2 層／核心）
- 四類符文的詞彙定義，依槽位職責分類
- 由內而外的解釋器：魔法陣 → 編譯後的法術
- 生命週期時間表與編譯期粒子預算
- 符文陣：由魔法陣自身的結構摘要導出的陣形幾何與自轉

**明確不做**：

- **不求值數學式**。符文可夾帶算式，但語言本身屬 [expr-language](../expr-language/design.md)；本子系統只決定式子掛在哪個槽位、吃哪一條時間軸。
- **不取樣粒子**。編譯後的法術是**資料**，把它變成某一幀的粒子緩衝是 [particle-simulation](../particle-simulation/design.md) 的事。
- **不認識 JSON 或任何文字語法**。核心只見結構化資料，文字↔資料在 [boundary-host](../boundary-host/design.md)。
- **不認識相機、螢幕、繪圖 API**。連「視錐」都不在本子系統的詞彙裡——只交保守包絡，判定是宿主責任。

## 對外契約（Public Interface & DTOs）

本子系統對外只賣兩樣東西：**一次編譯**與**一組靜態查詢**。消費者是 boundary-host（包裝給宿主）與 particle-simulation（取樣時消費編譯結果）。

### C1 編譯

| 條目 | 契約 |
|---|---|
| **C1.1 單張編譯** | 吃一張魔法陣，回傳「編譯後的法術」或一個編譯錯誤。純函數，同輸入同輸出 |
| **C1.2 多張合成** | 吃一串魔法陣，合成為一份法術：發射器與力場串接、預算相加、生命週期界標**逐界標取最大值**。空串列的結果等於單位元；單元素的結果等於單張編譯 |
| **C1.3 預算護欄** | 一個編譯期上限值。合成後的總量對同一個上限檢查，超過即編譯錯誤並回報「需求量／上限」 |

**編譯錯誤**目前只有一種：預算超額。核心不做其他防禦性檢查——不合法的槽位組合在**型別層就無法表示**，因此不需要被檢查出來。

### C2 編譯後的法術（DTO）

一份可序列化的純資料，六個組成：

| 組成 | 內容 | 誰消費 |
|---|---|---|
| 生命週期總長 | 最後一批粒子死盡的時刻 | 邊界層判斷法術是否結束 |
| 粒子總量 | 各發射器數量之和 | 配額記帳 |
| 預算計畫 | 逐發射器與總計的結構化預算 | 宿主查詢、緩衝配置 |
| 發射器集合 | 每個發射器帶：發動點與法線、粒子數、生成包絡、運動描述、外觀描述、所屬階段 | 取樣器 |
| 生命週期界標 | 繪製／收束／施放／消散的絕對時間點 | 取樣器與宿主 |
| 力場環境 | 陣的物理環境，直通不參與 fold | 力場層 |

**兩條凍結的性質**：運動與外觀都是**資料而非函數**，因此整份結果可序列化、可快取、可在編譯期做預算分析；發射器集合的順序即消費順序，不得重排。

### C3 靜態查詢

| 條目 | 契約 |
|---|---|
| **C3.1 階段查詢** | 給一份生命週期界標與一個時刻，回答該時刻屬於哪個階段。純查表，不是狀態機 |
| **C3.2 空間包絡** | 給施法上下文與一個發射器，回答一個**保守**的軸對齊包圍盒。逐位元凍結——宿主的剔除依賴它的穩定性 |
| **C3.3 形狀半徑** | 給一個初始面形狀，回答其外接半徑 |
| **C3.4 拖尾需求** | 回答這份法術是否需要速度資料。取樣器據此在進迴圈前選路徑，而非逐粒子分支 |
| **C3.5 元素外觀** | 給一個元素，回答其顏色曲線與混合模式。屬性只在 fold 第一步轉成外觀，影響面封閉 |
| **C3.6 區間算術** | 對算式做保守的區間求值。**內部面**，只開放給 boundary-host 的空間摘要，讓它能用同一份程式碼收緊界而不是複製一份 |

### C4 符文陣（凍結）

| 條目 | 契約 |
|---|---|
| **C4.1 結構摘要** | 給一張魔法陣，回答一個結構摘要值。**交付即凍結**——摘要決定陣的長相，改它等於靜默改變每一個法術的外觀。浮點必須以位元進入摘要，否則同一份輸入在不同平台畫出不同的陣 |
| **C4.2 陣形計畫** | 由摘要與結構導出一組筆畫，每筆帶種類、半徑、角度區間、粒子配額與自轉參數。**索引序即繪製序** |
| **C4.3 自轉角度** | 給自轉參數與**施法秒數**，回答旋轉角。時鐘是施法秒數而非粒子年齡——剛體旋轉是「同一瞬間每個點同角度」，用年齡驅動會把陣抹成螺旋 |

### 對外承諾的三條律

1. **空陣即素放**：所有槽位皆空的魔法陣走同一條 fold，產出跳過繪製與收束階段的預設放出發射器。無特例分支。
2. **開放擴充、凍結語意**：符文的分類型別可加成員；既有成員的語意與其序列化標籤不動。
3. **摘要即合約**：同一份輸入在同平台永遠畫出同一個陣。

## 內部模組劃分（Internal Modules）

| 模組 | 單一職責 |
|---|---|
| **M1 共用空間詞彙** | 抽象 3D 向量與平面基底、時間與秒數、種子、施法上下文、確定性隨機通道。全核心共用的地基——三個核心子系統都依賴它，它不依賴任何人 |
| **M2 結構** | 魔法陣的形狀：環、槽位、核心節點、陣層級屬性。**只有形狀，沒有語意**——這個模組不知道外圈符文是幹嘛的 |
| **M3 符文詞彙** | 四類符文與其值域，加上兩個「陣層級屬性而非符文槽」的型別（力場、發動點） |
| **M4 解釋器** | 由內而外的 fold、編譯後法術的組裝、預算護欄與預算計畫、空間包絡的區間算術、元素外觀查表 |
| **M5 符文陣** | 結構摘要、筆畫計畫、自轉參數與角度、筆畫取樣 |

依賴方向：`M1 ← M2 ← M3 ← {M4, M5}`，且 `M5 ← M4`（fold 第五步取用陣形計畫）。**子系統內無循環**。

## 資料流管線（Data Flow Pipeline）

```text
輸入      一張（或一串）魔法陣          ← boundary-host 解碼後交進來
  │
驗證      型別層已排除非法組合；
          執行期只檢查一件事：粒子總量是否超過護欄
  │
業務處理  由內而外 fold（五步）
          ① 核心   → 本質：屬性轉外觀、強度轉能量預算、節點轉方向偏置
          ② 內圈   → 行為：軌跡、時序包絡、玩家算式，組成運動描述
          ③ 夾層   → 調變：收束曲線、增幅、時序位移（界接內外的關鍵因子）
          ④ 外圈   → 展現：形狀取樣、範圍縮放、輻射模式展開為發射器集合
          ⑤ 陣形   → 由結構摘要導出筆畫，每筆成為一個陣形發射器
  │
輸出      編譯後的法術（純資料）
          ├─→ particle-simulation：逐幀取樣的輸入
          └─→ boundary-host：靜態查詢的資料來源
```

**沒有儲存與外部呼叫**——本子系統零 IO，管線是一條純函數鏈。①→④ 是主效果的支線，⑤ 是陣形的支線，兩者在輸出處併為同一個發射器集合，並以**所屬階段**欄位區分（力場只作用於施放階段的發射器，於是陣天然不被吹歪）。

## 模組間公開介面（Module Interfaces）

只列跨模組呼叫的**契約**；型別由實作決定，屬 Level 3。

| # | 呼叫方向 | 契約內容 |
|---|---|---|
| **I1** | M2 → M3 | 槽位的型別約束：外圈槽位只接受展現類符文、內圈只接受行為類。**不合法的組合不可表示**，這是解釋器不需要防禦性檢查的原因 |
| **I2** | M3 → M1 | 符文的值域以共用詞彙表達（向量、秒數、算式） |
| **I3** | M4 → M2 | 讀取結構：逐環、逐槽位、核心節點、陣層級屬性 |
| **I4** | M4 → M3 | 對每個符文分派 fold 步驟；新增符文成員時由編譯器窮盡性檢查列出所有待補位置 |
| **I5** | M4 → M5 | fold 第五步取用陣形計畫，把每筆筆畫轉成一個發射器 |
| **I6** | M5 → M2、M5 → M3 | 摘要涵蓋結構與符文槽；**陣層級屬性刻意不進摘要**——掛一個力場不該靜默重畫這張陣 |
| **I7** | M4 → M1、M5 → M1 | 座標系、時間、確定性隨機 |

## 使用的技術

沿用主架構技術棧。子系統特有的只有一件事：**依賴白名單**——核心 sublibrary 的可用依賴是一份短清單，由測試機械守護。本子系統因此碰不到 IO、碰不到效果型別、碰不到序列化函式庫。

## 開發階段

對應主架構 P1（骨架與語意）與 P5（深化）。內部里程碑三個，皆已達成：

| 里程碑 | 內容 |
|---|---|
| **M1 結構與解釋器** | 陣可以被折成發射器；空陣即素放 |
| **M2 陣形自身** | 陣變成看得見的線、活滿整場、會轉 |
| **M3 語彙廣度** | 四個分類型別的值域由概念驗證的最小集擴到可玩 |

這是全專案最長的串行鏈——解釋器與符文陣兩個模組是多輪工作的共同交集，很難平行。

### circle-interpreter

- **階段**：階段一（已交付）
- **負責模組**：M2 結構、M3 符文詞彙、M4 解釋器
- **實作的 Level 2 介面**：C1.1 單張編譯、C1.3 預算護欄、C2 編譯後的法術、C3.5 元素外觀；建立 I1、I3、I4
- **資料流管線段落**：從「輸入一張魔法陣」到「輸出編譯後的法術」的 ①～④ 全段
- **當初的驗收標準**：任一魔法陣都能折成發射器集合；全空的魔法陣產出的發射器與骨架時期的素放行為等價；不合法的槽位組合無法被建構
- **明確不做**：不碰陣形（⑤ 屬 #3）、不求值算式、不取樣

### expr-rune-wiring

- **階段**：階段一（已交付）
- **負責模組**：M3 符文詞彙、M4 解釋器
- **實作的 Level 2 介面**：無新增，擴充 C2 的運動與外觀描述；使用 I4
- **資料流管線段落**：②（內圈→行為）與 ③（夾層→調變）
- **當初的驗收標準**：四種夾帶算式的符文都能影響粒子；分層時間軸成立——行為層的時間變數是粒子年齡、調變層的是施法秒數，兩者在同一份法術裡並存不互相污染
- **明確不做**：不定義算式的文法與求值（屬 expr-language）；不改變既有非算式符文的行為

### lifecycle-formation

- **階段**：階段一（已交付）
- **負責模組**：M4 解釋器
- **實作的 Level 2 介面**：C2 的生命週期界標、C3.1 階段查詢；fold 第五步
- **資料流管線段落**：⑤（陣形支線）與輸出處的兩支線合併
- **當初的驗收標準**：四階段界標由陣層級屬性算出且單調不減；缺該屬性的魔法陣退化為即時施放且輸出與加入界標前逐位元相同；陣形發射器帶「繪製」階段標記，因而不受力場影響
- **明確不做**：不決定陣形的幾何長相（那是 #4 用摘要導出的）；不做階段的視覺差異化

### sigil-geometry

- **階段**：階段二（已交付）
- **負責模組**：M5 符文陣、M4 解釋器（一處接線）
- **實作的 Level 2 介面**：C4.1 結構摘要、C4.2 陣形計畫；使用 I5、I6
- **當初的驗收標準**：同一份魔法陣永遠得到同一組筆畫；不同的魔法陣得到不同的筆畫；粒子的索引順序就是筆畫被畫出來的順序（陣是被畫出來的線，不是霧）；陣層級屬性改變不影響摘要
- **資料流管線段落**：⑤ 的前半——從結構與摘要到筆畫計畫
- **明確不做**：不表義（筆畫只是線段，不承載字義）；不做立體堆疊

### sigil-persistence

- **階段**：階段二（已交付）
- **負責模組**：M4 解釋器
- **實作的 Level 2 介面**：無新增，修改 C2 的陣形發射器生存窗
- **資料流管線段落**：⑤ 的後半——陣形發射器的生成包絡
- **當初的驗收標準**：陣從畫出來到法術結束都存在，法術是從仍然存在的陣中射出而不是把陣燒掉；取消陣形收束後，繪製窗內的輸出與交付前逐位元相同
- **明確不做**：不讓陣的終點可調（屬 #8）；不改變玩家夾層收束符文對主效果的既有語意

### sigil-motion

- **階段**：階段二（已交付）
- **負責模組**：M5 符文陣
- **實作的 Level 2 介面**：C4.3 自轉角度；擴充 C4.2 的筆畫參數
- **資料流管線段落**：⑤ 產出的筆畫在取樣時被旋轉（角度由本卡提供）
- **當初的驗收標準**：整陣繞面心自轉、相鄰環反向、蓄力段角速度攀升後恆速；角速度有上界，法術跑再久都不發散；靜態的陣（時間為零）與加入自轉前逐位元相同
- **明確不做**：不做非等速自轉（屬 #10）；不做節點群公轉（屬 #9）；不用粒子年齡驅動旋轉

## Feature 契約卡

### sigil-time-axis

- **驗收標準**：陣可比法術晚收或早收，且不論參數多極端，陣至少活到畫完；開啟凍結後陣在畫完之後外觀恆定但仍自轉；沒有設定這個屬性的魔法陣輸出逐位元不變；結構摘要不因這個屬性改變

### node-orbit

- **資料流管線段落**：⑤ 的筆畫參數，取樣時生效
- **驗收標準**：核心的四個方向節點可繞陣心公轉，與整陣自轉並存且兩者角速度獨立；未啟用時輸出逐位元不變

### time-varying-modulation

- **階段**：階段四（候選）
- **負責模組**：M3 符文詞彙、M4 解釋器、M5 符文陣
- **實作的 Level 2 介面**：擴充 C2 的力場環境（參數可為時間函數）與 C4.3（角速度可為時間函數）；需要 expr-language 提供第四種時間掛載點的求值環境
- **資料流管線段落**：③（調變）與 ⑤（自轉參數）
- **驗收標準**：力場強度與自轉角速度都能以算式描述並隨施法秒數變化；常數算式的結果與現行固定參數逐位元相同
- **明確不做**：不讓力場參數吃粒子年齡（力場是陣的環境，不是粒子的屬性）；不改變既有三種時間掛載點的語意

### glyph-semantics

- **階段**：階段四（候選）
- **負責模組**：M5 符文陣

- **驗收標準**：字符筆畫能被辨識為特定字元而非任意線段；字符的選擇由結構摘要決定，因而同一份魔法陣永遠得到同一組字符

### spell-cost-model

- **階段**：階段四（候選）
- **負責模組**：M4 解釋器
- **實作的 Level 2 介面**：擴充 C1.3 預算護欄，新增一個以遊戲層詞彙表達的代價維度；可能新增一種編譯錯誤
