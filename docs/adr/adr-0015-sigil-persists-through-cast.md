# ADR-0015：陣駐留到法術結束——取消陣形收束，逐位元邊界收窄

- 狀態：已採納（2026-08-15）
- 相關：[architecture.md §3.3（生命週期——本 ADR 修訂其狀態圖）](../architecture.md)；ADR-0010 D6（只有施放粒子吃力場）、**ADR-0014 D5（其逐位元豁免邊界由本 ADR 取代）**；spec 0006 §4.3（陣形包絡推導鏈——本 ADR 撤銷其第 2／3 步）、spec 0016 §1-5（Casting 相位零影響律——本 ADR 撤銷）；落地 spec：0017

## 背景

spec 0006 建立的生命週期是：畫陣 → 陣向中軸塌縮 → 陣在 `castStart` 全數死盡 → 主效果發射。0016 把陣的幾何從「霧」換成「筆畫」之後，這條時間軸的代價變得刺眼：玩家好不容易看清楚的符文陣，在法術真正開始的那一刻**整個消失**。畫面讀起來是「陣被燒掉換成法術」，而不是「法術從陣裡射出來」——後者才是這個系統一直在描述的東西（architecture §1.2「特效即魔法」）。

使用者裁決（2026-08-15）：**魔法陣會存在持續到魔法施放完畢。**

要兌現它必須先回答一個問題，因為兩者是綁在一起的：收束曲線 `kc = clamp((castStart − t)/phConverge, 0, 1)` 在 `t > castStart` 之後恆為 0，代表側向分量全塌到軸上。**只把生存窗拉長而不動收束，得到的不是一個持續存在的陣，是一條豎直的線。**

## 決策

**D1（陣形生存窗延長至 `ppEnd`）** 陣形發射器的 `envDuration` 由 `castStart − formLife` 改為 `ppEnd − formLife`：最後一批陣形粒子與最後一批施放粒子**同時**死盡。「施放完畢」取整個法術的終點，不取施放生成窗關閉的時刻——陣與法術一起收場。

`envDelay`（0）與 `envLifetime`（`min 0.6 (castStart/2)`）的算式**一字不動**。這是本決策能這麼便宜的全部原因：`firstBirth env n i = envDelay + (i/n)·envLifetime` 只讀這兩欄，`envDuration` 只出現在存活判定裡。所以畫陣的節奏、`skPhase`、索引序＝繪製序（0016）全部不受影響——**取樣器一行沒改，也沒有任何新機制或新狀態**。

**D2（取消陣形收束，不做成開關）** 陣形發射器的 `motConverge` 恆為 `Nothing`；`kcExprFor` 整個刪除。Converging 這個階段的語意由「陣向核心收攏」改為「陣原地駐留、蓄力」，`phConverge` 保留它既有的算術作用（`castStart = phDraw + phConverge`，決定主效果何時開始），只是這段時間裡陣在做的事不同了。

做成可選開關被否決：那需要在 `phases` 加鍵、在兩種語意間分岔、並讓兩條路徑各自長期受測，成本遠高於它的價值——沒有任何需求說「有些陣要塌、有些不要」。玩家自己的 `ConvergeRune` **完全不受影響**：spec 0004 凍結它為施放發射器的調變曲線，它現在仍然是。

**D3（`emPhase = Drawing` 不動，於是陣天然不吃力場）** 陣形發射器維持 `emPhase = Drawing`。它是純中繼資料（取樣器不讀），但力場層依它判斷（ADR-0010 D6）。於是駐留期間的陣**不會被力場吹歪**——重力井吸得動法術，吸不動陣。這正是想要的語意（陣是幾何，不是被吹的煙），而且零額外程式碼。

順帶把 D6 的保證變得**真的可測**：在此之前，`castStart` 之後根本沒有陣形粒子活著，這條保證在施放期是空的；現在它是一條有內容的律，由 `test/PersistWiringSpec.hs` 在力場正在扭曲隔壁施放粒子的同時，斷言陣形列的位移恆為零。

**D4（逐位元豁免邊界收窄，取代 ADR-0014 D5）** ADR-0014 D5 寫的是「豁免只到 Drawing／Converging 為止」，其前提正是陣形在 `castStart` 死盡；該前提已被 D1 撤銷。新的邊界：

> **`t < min(phDraw, castStart − formLife)` 的每一幀逐位元不變**；無 `phases` 的法術完全不受影響。

兩項限制各自的來源不同，都必須算進去：
- `phDraw`——收束曲線在 `t ≤ phDraw` 恰等於 1，而取樣器算的是 `pos = raw − (1 − kc)·trans`，`kc = 1` ⇒ 減 `vscale 0 trans` ⇒ IEEE 上逐位元恆等。過了 `phDraw` 舊碼開始塌縮，新碼不塌，位置本來就該不同。
- `castStart − formLife`——舊的生成窗在此關閉，陣形粒子開始不再重生。**而這個時刻可能早於 `phDraw`**（`⟺ phConverge < formLife`）：`bare-sigil` 的生成窗在 0.9 s 關閉，比它的 `phDraw = 1.0 s` 還早，也就是說**舊碼的陣在還沒畫完的時候就已經開始消散了**。這是實作 0017 時由 golden 照出來的，設計時沒有預見（func-spec 0017 §9.4-1）。

實測與此完全吻合：`grand-sigil`（`phConverge` 0.6 ≥ `formLife` 0.6）邊界＝`phDraw` 1.2 s ＝幀 71；`bare-sigil` 邊界＝0.9 s ＝幀 54。兩個 golden 與 `FieldPlumbingSpec` 的兩個摘要因此重錄。

## 被否決的方案

- **只延長生存窗、保留收束曲線**——`kc` 在 `castStart` 之後恆為 0，陣會塌成一條豎直的線。這不是「持續存在的陣」。
- **收束到一個下限（例如 85% 半徑）後駐留**——保留了 Converging 的視覺意義，但引入一個沒有依據的魔術常數，且「縮一點點」在畫面上讀不出是刻意的還是 bug。使用者裁決取原地駐留。
- **陣在 `castStart` 塌縮消失、Casting 期再重新展開**——Drawing／Converging 可逐位元不變，相容性最好；但畫面上多一次「消失又出現」，而且要第二段包絡、發射器數翻倍。
- **把收束做成 `phases` 的可選鍵**——見 D2。
- **陣的獨立終點（例如法術結束後陣再留一會）**——需要新的 JSON 鍵（`phases.linger` 之類），屬 schema 擴充；記帳於 func-spec 0017 §8-3。
- **靜止不重畫的陣**——需要把 `envLifetime` 拉到整場，會讓 `firstBirth` 把出生時刻攤到整場、陣要畫一整場才畫完，直接違反 0016 的「索引序＝繪製序」。記帳於 0017 §8-1。

## 後果

**正面**：
- 法術**從陣裡射出來**：Casting 期間陣與主效果並存（手動 smoke：`grand-sigil` 於 age 3.12 s、1554 粒，火元素粒子噴穿仍然完好的陣；`lattice-seal` 於 age 5.58 s、1390 粒仍完整）。
- 順手修掉一個沒人發現的舊行為：`phConverge < formLife` 的陣（例如 `bare-sigil`）**在畫完之前就開始消散**。現在陣一定會被畫完。
- ADR-0010 D6 的「只有施放粒子吃力場」從空保證變成有內容的受測律。
- 預算與合約零變更：`emCount` 一個沒動 ⇒ `spellBudget`／`ParticleBudget` 逐欄位相同；`Magic.Codec` 零觸碰、schema 不升版、C ABI 不動。

**負面／記帳**：
- 同時存活的列數在施放期增加約 1600（陣形滿編）。依 0010 量到的 65 ns/粒約 **+0.1 ms/幀**，在 16384 的 `budgetCap` 與 2 ms 的單幀預算內可忽略，但這是本輪唯一的執行期成本。
- 兩個 golden 與兩個摘要在 0016 之後**再度**重錄。逐位元邊界已由本 ADR 明文釘死，未來任何再動陣形時間軸的變更都要重付這筆。
- Converging 這個階段名稱與它現在做的事（駐留蓄力）不再完全貼合。改名要動 `Phase` 建構子＝C 線碼（ADR-0011 D7 的純增補律），代價遠大於收益，故保留名稱並在 architecture §3.3 註明語意。
- 陣形旋轉／動態陣形（0006 §9、0016 §8-3）變得更值得做——一個只存在 1.5 秒的陣沒什麼好轉的，一個存在整場的陣有。
