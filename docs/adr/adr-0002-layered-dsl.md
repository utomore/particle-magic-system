# ADR-0002：分層式 DSL，不採深度 GADT DSL

- 狀態：已採納（2026-08-11）
- 相關：[architecture.md §4](../architecture.md)

## 背景

「Circle as Data」需要決定資料表示的深度：太淺（純參數紀錄）表達力受限於預定義參數組合，違背「無窮無盡的魔法」的願景；太深（完整型別化表達式語言）則解釋器、序列化、版本演進成本在 POC 階段過高。

## 決策

採**三層式表示**：

1. **結構層**：魔法陣幾何 ADT（`Circle`：環/槽位/核心），槽位型別依職責區分。
2. **參數層**：行為參數紀錄（軌跡、包絡、形狀、屬性等具名資料）。
3. **表達式層**：小型數學 AST（`Expr`）——封閉、一階、無遞迴綁定、求值必然終止。只在明確的插槽（`FormulaRune`、收束曲線、範圍、尺寸）接受表達式。

解釋器 `compile :: Circle -> Either CompileError CompiledSpell` 將三層編譯為發射器集合。

## 後果

**正面**：
- 表達力有實質的開放性（玩家可寫任意數學式），但語言面積小到可以完整測試與序列化。
- `Expr` 無綁定、無遞迴 ⇒ 求值必然終止、可靜態分析（常數摺疊、範圍估計）、Aeson 序列化直截了當。
- 每層可獨立擴充：加符文不動 Expr，加運算子不動結構。

**負面**：
- 玩家無法定義抽象（函數、變數綁定、遞迴）——「魔法即程式」的終極形態被排除在外。
- 表達式插槽的位置是設計時決定的；玩家不能把式子放到未預留的參數上。
- 若未來要升級成深度 DSL，`Expr` 可以嵌入為子語言，但結構層語意需要重新設計。

## 被否決的替代方案

- **純參數紀錄**：實作最快，但魔法的多樣性完全受限於參數組合空間，玩家只能「調參」不能「創造公式」，違背核心願景。
- **完整深度 DSL（GADT / tagless-final）**：魔法即程式、表達力無上限。但 GADT 的 JSON 序列化與 schema 版本演進非常困難，型別檢查器要自己寫，解釋器複雜度數倍——POC 階段風險過大。保留為長期可能的演進方向（Expr 可作為其子集嵌入）。
