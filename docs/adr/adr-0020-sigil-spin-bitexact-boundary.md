# ADR-0020：陣會自轉——逐位元邊界收窄至 `t = 0`,並終結陣形 golden 的逐位元記帳

- 狀態:已採納(2026-08-16)
- 相關:[architecture.md §3.3(生命週期)、§4.3(分層時間軸)](../architecture.md);**ADR-0015 D4(其逐位元邊界敘述由本 ADR 取代)**、ADR-0015 D1／D2／D3(駐留、無收束、陣不吃力場——三條皆為本 ADR 的前提,不受影響)、**ADR-0014 D5(已於 ADR-0015 被取代,本 ADR 再取代一次)**;spec 0016 §1-5(已由 ADR-0015 D4 撤銷)、spec 0017 §9.2(第二次重錄的實測);落地 spec:0020

## 背景

陣形時間軸至此被動過三次:

| 輪次 | 動了什麼 | 逐位元邊界 |
|---|---|---|
| 0016 | 陣形幾何由「霧」換成「筆畫」 | Drawing／Converging 兩相位豁免(ADR-0014 D5) |
| 0017 | 生存窗延長至 `ppEnd`、取消收束 | `t < min(phDraw, castStart − formLife)`(ADR-0015 D4) |
| **0020** | **陣自轉** | **本 ADR** |

ADR-0015 的負面記帳明文寫著:

> 「兩個 golden 與兩個摘要在 0016 之後**再度**重錄。逐位元邊界已由本 ADR 明文釘死,未來任何再動陣形時間軸的變更都要重付這筆。」

本輪就是那個「未來」。付這筆之前值得先問一句:**這筆錢買到了什麼?**——三輪下來,陣形 golden 每一輪都被重錄,而每一輪重錄之後它保護的都只是「上一輪的陣長什麼樣」,不是任何宿主真正依賴的東西。這個問題的答案就是本 ADR 的 D3。

## 決策

**D1(逐位元邊界收窄至 `t = 0`,取代 ADR-0015 D4)** 新的邊界:

> **`t = 0` 的那一幀逐位元不變;`t > 0` 起陣形粒子的位置改變。無 `phases` 的法術完全不受影響,施放粒子於全部時刻逐位元不變。**

`t = 0` 這一格不是修辭。func-spec 0020 §2.4 把自轉的起始相位**併進 0016 既有的 `skPhase`** 而不是新增一個欄位,於是 `spinAngle sp 0 = 0` 恆成立,靜態的陣**沒有被改變,只有時間讓它轉**。誠實地說這個邊界幾乎是空的——實測第一個差異幀就是 golden 的幀 0(該幀已經是 `t = 1/60 s > 0`)——但它讓「本輪只動時間、不動幾何」這句話有一個可測的見證,而不是一句自我聲明。

同一個 §2.4 的選擇還買到一個更有價值的東西:0016 的**幾何導出結果逐位元不變**。本輪從摘要多讀 14 個位元(`dl` 的 34..47),而那段與 0016 用掉的位段不相交;`test/SigilMotionSpec.hs` 以改動前擷取的 18 個幾何摘要釘死這件事。**沒有任何一個既有法術被重新畫過**——變的只有它怎麼動。

**D2(兩條零影響律,明文區分保護對象)** spec 0016 §1-5 的「Casting 相位零影響律」已由 ADR-0015 D4 撤銷(其前提「陣在 `castStart` 死盡」不再成立)。取代它的兩條律**不以相位為主語,以發射器為主語**,因此不會再被時間軸的變動掀翻:

1. **主效果零影響律**——施放發射器走 `SpawnAtAnchor`／`SpawnOnShape`,**永不**走 `SpawnOnStroke`,故自轉在結構上就到不了它。施放粒子的輸出於**全部相位、全部時刻**逐位元不變。
2. **無 `phases` 零影響律**——無 `phases` ⇒ 無陣形發射器 ⇒ `FrameOutput` 完全不受影響、golden 零重錄。

這兩條才是宿主真正依賴的東西,而它們**至今從未被破壞過**:0016、0017、0020 三輪全部成立。`test/SigilMotionWiringSpec.hs` 把第一條做成差分見證(同一份 `CompiledSpell`,把每個 `skSpin` 歸零之後重新取樣,施放列逐位元相同、陣形列不同),第二條做成 8 個無 `phases` 範例的逐時刻比對;`test/PerfGoldenSpec.hs` 的 8 個 golden 未重錄則是它的端到端見證。

**D3(陣形 golden 改為結構性斷言;本輪是最後一次逐位元重錄)** 裁決如下:

> `test/golden/perf-0010/{bare,grand}-sigil.txt` 與 `test/FieldPlumbingSpec.hs` 對這兩個範例的摘要,其**陣形部分**的逐位元價值已耗盡。下一輪起改為**結構性斷言**——粒子數、`strokeRadius` 界、對稱性、存活窗——而非逐位元比對。逐位元保護集中在**施放粒子**與**無 `phases` 的法術**上(D2 的兩條律),那才是宿主依賴的東西。

理由是實測而非美學。三輪重錄之後,這兩個檔案在陣形部分能抓到的唯一一類錯誤是「陣的長相變了」,而那件事現在有更精確、更快、也更會說話的守衛:`test/SigilMotionSpec.hs` 的幾何摘要(能指出**哪個**圓的幾何動了)、`test/SigilSpinSpec.hs` 的等距同構律(能指出**哪條**律破了)。相對地,一個 240 幀的 FNV 摘要只會說「不一樣」。

**執行留給下一輪**,本輪仍照舊重錄:把 ADR 的裁決與它的執行放進同一個 PR,會讓「這次重錄是對的嗎」和「以後還要不要重錄」兩個問題混在一起審。

## 被否決的方案

- **不動邊界,把自轉做成 opt-in 的 JSON 鍵**——可保逐位元全等,但陣是**導出**的指紋而不是作者資料(0016 §8-2 的裁決),加鍵等於推翻它;而且「有些陣會轉、有些不會」沒有任何需求支持。記帳於 0020 §8-1。
- **自轉角取自粒子年齡**——不必碰施法時鐘,但那不是剛體旋轉:同一時刻不同年齡的粒子被轉到不同角度,陣會被抹成螺旋。0017 讓陣以 `formLife` 為週期循環重生之後,這個錯誤還會讓陣每個週期抖一次。
- **繞筆畫自身中心自轉(節點原地打轉)**——保長律會破,`strokeRadius`／`emitterBounds`／spec 0010 的剔除全部要跟著改,`Compile.hs` 進入修改清單,與 spec 0025 的平行也就沒了。繞面心是對的選擇,理由不只是好看。
- **純二次角度函數(沿用 0017 之前的初稿)**——陣只活 1.5 秒時安全,活滿整場(6.9／8.1 秒)時角速度無界:`ω(8.1) ≈ 3.3 rad/s`,陣在法術尾聲會轉成一個模糊的碟子。改為分段(蓄力段二次、施放後恆速),角速度上界 `|rate| + |accel|·castStart` 與法術總長無關。
- **本輪就把陣形 golden 改成結構性斷言**——見 D3 末段:裁決與執行分開審。

## 後果

**正面**:

- 陣看起來像**正在運作的機關**而不是貼圖:整陣繞面心自轉、相鄰環反向、蓄力段轉速攀升後維持恆速。0017 讓陣活滿整場,這件事的價值才兌現得出來——觀眾有 6–9 秒可以看見它在動。
- **成本異常地低**:`Magic.Compile` 零觸碰(等距同構律的直接後果,§2.2)、`Magic.Codec` 零觸碰、schema 不升版、不加符文、不加 JSON 鍵、不加依賴、無新的跨幀狀態(`spinAngle` 是 `t` 的純函數,快轉／倒帶／重播照舊成立)。`sampleStroke` 的六種閉式定義一個字都沒改。
- 0016 的三條律(索引序＝繪製序、n 臂等分旋轉對稱、`|p| ≤ strokeRadius`)**由保長性結構性推得**而非重測一次;第三條讓 `emitterBounds` 與 spec 0010 的視錐／時間窗剔除零變更。
- ADR-0015 D3(陣不吃力場)在陣會動之後仍然成立且更有內容:重力井吸得動法術,吸不動一個**正在轉**的陣。
- **一條長期的循環被終結**(D3):不再每輪重錄陣形 golden、每輪聲稱有保護。

**負面／記帳**:

- 兩個 golden 與兩個摘要**第三度**重錄。這是最後一次(D3)。
- 每個陣形粒子每幀多兩次三角函數與四次乘加。陣形滿編約 1600 粒,`sin`／`cos` 各約 20 ns,約 **+0.06 ms/幀**,與 0017 的 +0.1 ms 同一量級,在 2 ms 的單幀預算內可忽略。可優化(每發射器每幀算一次 `(cos, sin)` 而非每粒子一次)但本輪不做:`positionIn` 的簽名與 `EmitterFrame` 的內容都屬 spec 0010 凍結面,為 0.06 ms 動它不划算,記帳於 0020 §8。
- **節點群不公轉**。0020 §3.2 原本要求節點群整體繞面心公轉,但節點發射器走 `SpawnAtAnchor` + 固定 `anchorOffset`,不走 `SpawnOnStroke`;要它公轉必須改 `Magic.Compile`,而 `Compile.hs` 零觸碰正是本輪與 spec 0025 能平行的根據。故本輪只轉筆畫,節點與中心維持不動(中心不動本來就是設計要的視覺定錨點)。記帳於 0020 §8-9。
- 「相鄰層反向」以**繪製序**而非**層索引**判定。層索引奇偶在中間有空層時會讓兩個相鄰**畫出來**的環同向(實測 `grand-sigil` 的 idx 1,3,4,5),讀起來像 bug。改以繪製序後外框與各環一律交替,結構性依然成立。記帳於 0020 §9.4-3。
